### เป้าหมาย
- ระบบบันทึกทรัพย์สิน / หนี้สิน / รายได้ / ค่าใช้จ่ายของ **ครอบครัวเดียว** → Net Worth รายเดือน (ทั้งครอบครัวและรายคน) · ปิดงวดเป็น Snapshot
- เจ้าของระบบไม่ใช่โปรแกรมเมอร์ → ทุกการเปลี่ยนแปลงอธิบายเป็นภาษาไทย + ขั้นตอนคลิก + เช็กลิสต์ทดสอบ
- ตอนนี้: ปรับเมนู / การทำงาน + ทดสอบบนข้อมูล "เกือบจริง" ให้จบ → ล้างข้อมูล → Bootstrap ใหม่ → AI นำเข้าข้อมูลจริง → Confirm Go-live

### วิธีทำงานที่ตกลงกัน (ทุกงาน)
- แก้บน branch → เปิด PR (`gh api repos/accountoei/oeiwealth/pulls`) → เจ้าของกด Merge → Vercel deploy เอง
  - ยกเว้น PR ที่แก้**เฉพาะเอกสาร** (`docs/`, `*.md` — ไม่แตะโค้ด / migration / Edge Function / workflow) AI Merge เองได้ แล้วแจ้งเจ้าของ
- migration ใหม่ = ไฟล์ใหม่เสมอ (ห้ามแก้ไฟล์ที่รันแล้ว) · **AI รันเองผ่าน Supabase connector** ตามลำดับใน `AGENTS.md` §2: ผ่านชุดทดสอบ → เปิด PR → รันไฟล์นั้นแบบตรงตัว → ตรวจผล (ตาราง / RLS / advisors) → รายงานเจ้าของ → เจ้าของกด Merge
  - ต้องถามเจ้าของก่อนถ้า migration ลบ / เปลี่ยนชื่อตารางหรือคอลัมน์ หรือแก้ข้อมูลที่มีอยู่ · ถ้าไม่มี Supabase connector ให้เจ้าของรันเองใน SQL Editor แบบเดิม
- ก่อน push: `DB=fwv_test bash tests/run.sh --scenario` (ล่าสุด **318 checks**, เฉพาะ Postgres ในเครื่อง) + `tsc` + `eslint` + `next build`
- ทุก PR อัปเดตไฟล์นี้ (แถวการตัดสินใจ + แถวประวัติ PR) และจำนวน checks ใน `AGENTS.md`
- ปิดงานด้วยภาษาไทย 3 ส่วน: เปลี่ยนอะไร · ต้องทำอะไร (migration / Merge) · เช็กลิสต์ทดสอบด้วยข้อมูลสมมติ

### ปัญหาที่ค้างอยู่
- **หน้าค้าง / ไม่อัปเดตหลังบันทึก (ยังไม่ยืนยันว่าหาย):** 15 ต.ค. แยกรายการแล้วปุ่มค้าง "…" — ฐานข้อมูลบันทึกสำเร็จ และ Server render เสร็จใน ~2 วิ (ดูจาก Supabase logs) แต่หน้าจอไม่อัปเดต · จำลองในเครื่องไม่เกิด · ข้อสังเกต: เกิดหลังเปิดหน้าค้าง ~30 นาที (middleware ต่ออายุ token ระหว่าง server action) · แก้แล้ว: `router.refresh()` หลังบันทึกสำเร็จ (Undo / Dismiss / Split) + `history.replaceState(null, …)` ให้ Next.js รู้ URL · ถ้ายังเกิด: ขอเวลาที่เกิดจากเจ้าของ แล้วดู Supabase edge logs ช่วงนั้น · พิจารณาเพิ่ม refresh หลังบันทึกในฟอร์มอื่นด้วย
- ฟอร์มอื่นที่ใช้ `useActionState` ยังพึ่ง `revalidatePath` อย่างเดียว (ถ้าปัญหาด้านบนเกิดอีก อาจต้องใช้ hook refresh แบบเดียวกันทุกฟอร์ม)
- หน้า Income & Expenses โหลดข้อมูลทุกแท็บในครั้งเดียว (~30 query) — ยังเร็วพอ (~1 วิ ฝั่ง Server) แต่ถ้าข้อมูลจริงมากขึ้นอาจต้องแยกโหลดตามแท็บ
- เอกสาร Physical Schema ยังเป็น V1.1 (ฐานข้อมูลจริงมีตาราง / ฟังก์ชันเพิ่มหลายตัว)

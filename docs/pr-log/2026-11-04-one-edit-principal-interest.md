## เปลี่ยนอะไร
- ใหม่ `src/components/PairEdit.tsx`: ปุ่มเดียวเปิดหน้าต่าง "แก้ไขการรับชำระ" / "แก้ไขการจ่ายชำระ"
  - ช่อง วันที่ (ใช้กับทั้งเงินต้นและดอกเบี้ย) · เงินต้น · ดอกเบี้ย · ภาษีหัก ณ ที่จ่าย (เฉพาะฝั่งรับ)
  - แสดง "เงินเข้าบัญชี" (เงินต้น + ดอกเบี้ย − ภาษี) / "จ่ายออกจากบัญชีรวม" ตามที่พิมพ์
  - วันที่เดิมของเงินต้นกับดอกเบี้ยไม่ตรงกัน → แจ้งว่าบันทึกแล้วจะใช้วันที่เดียวกัน
  - ปุ่ม "ลบรายการนี้" (ลบทั้งก้อน `UndoButton PAYMENT`) อยู่ข้างปุ่มบันทึก
- `src/lib/records.ts` `updatePaymentPair`: ตรวจยอดก่อน (ตรงกับ CHECK ในฐานข้อมูล) → บันทึกเงินต้น (`cash_movements`) → ดอกเบี้ย (`income_transactions` / `expense_items`)
  - เงินต้นไม่ผ่าน = ไม่มีอะไรถูกแก้ · ส่วนที่ไม่เปลี่ยนไม่ส่งไปบันทึก · สิทธิ์ / งวดปิด / Trigger เหมือนการแก้ทีละรายการ
  - ถ้าดอกเบี้ยไม่ผ่านหลังเงินต้นบันทึกแล้ว → ข้อความบอกชัดว่าเงินต้นบันทึกแล้ว ให้แก้ดอกเบี้ยแล้วกดบันทึกอีกครั้ง
- ใช้ที่:
  - หน้ารายละเอียดเงินให้กู้ (แถวรับชำระล่าสุดในตารางผ่อน): "แก้เงินต้น" + "แก้ดอกเบี้ย" → "แก้ไข"
  - แท็บบันทึกรับของเงินให้กู้: บรรทัด "เงินต้น …" + "ดอกเบี้ย …" → บรรทัดเดียว "รับชำระ 5 ต.ค. · ยอดรวม ✎" (`recPair` ใน `src/lib/recorded-edit.tsx`)
  - แท็บบันทึกจ่ายของหนี้สิน: → "จ่ายชำระ 5 ต.ค. · ยอดรวม ✎"
- ปุ่มลบทั้งก้อนย้ายมาข้างปุ่มบันทึก (เดิมอยู่ด้านล่างแยกเส้น) ในกรณีที่ยังแก้ทีละส่วน: แถวดอกเบี้ยในหน้ารายได้ / ค่าใช้จ่าย และรายการที่เงินต้นเป็นรายการที่ระบบสร้าง (ฝั่งผู้กู้ของเงินกู้ในครอบครัว)
  - `RowActions`: แถวปุ่มอยู่นอก `<form>` (ปุ่มบันทึกผูกด้วย `form={id}`) → ปุ่มลบที่มีฟอร์มของตัวเอง (`deleteControl`) วางข้างปุ่มบันทึกได้โดยไม่ซ้อนฟอร์ม · `recEdit` รับ `deleteControl` แทน `extra`
  - `UndoButton` เพิ่ม `size="md"` (ขนาดเท่าปุ่มบันทึก)
- ปุ่มของรายการเดี่ยวในตารางผ่อน: "แก้ไข / ลบ" → "แก้ไข" (ปุ่มลบอยู่ในหน้าต่าง ข้างปุ่มบันทึก)

## การตัดสินใจที่ตกลงแล้ว
| เรื่อง | ตกลง |
|---|---|
| แก้การรับ / จ่ายที่มีเงินต้น + ดอกเบี้ยครั้งเดียวกัน | ปุ่มเดียว หน้าต่างเดียว บันทึกครั้งเดียว · ไม่ใช้ SQL (บันทึกเงินต้นก่อน แล้วดอกเบี้ย) |
